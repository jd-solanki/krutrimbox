# Select the reasoning effort per run and per Agent Action

krutrimbox lets an operator choose the **Reasoning Effort** an Agent Backend spends — how hard the Model thinks, a third axis orthogonal to the Agent Backend (which CLI) and the Model (which LLM) — through an optional `kb run --effort <level>` flag and an optional `effort` field on a config `agent` Hook Action. The value is passed through verbatim to the backend's own effort surface inside `buildExecCommand` — Claude Code's first-class `--effort <level>` flag, Codex's `-c model_reasoning_effort="<level>"` config override — and when omitted the backend CLI auto-picks its default. A run-level `--effort` is the default for the whole Factory Run and a per-step `effort` overrides it, exactly like the Model (ADR-0023). As with the Model, one Agent Backend serves the entire lifecycle, so a run's Reasoning Effort always belongs to that one backend's level vocabulary.

Reasoning Effort is deliberately **passthrough with no krutrimbox-side validation, allowlist, or fallback** — even though its level set is small and closed enough that an allowlist would be cheap, unlike the churning Model catalog. Three reasons. First, each backend already handles a bad value on its own: Claude Code validates locally, warns, and falls back to its default (exit 0); Codex silently coerces a CLI-known but model-unsupported level to the nearest supported one, and hard-fails only on a level its build does not recognize. Second, a per-backend allowlist would be both fragile and incomplete: Codex's effort validity is per-model and per-CLI-version (`xhigh` and `minimal` are model-gated, and the known-level enum changes between builds), so a model-blind list accepts levels a given model cannot do and can drift from the installed CLI's enum. Third, it keeps Reasoning Effort's contract identical to the Model's. The consequence is a safe-but-asymmetric failure mode: an invalid effort is softened by Claude and may fail the run loudly on Codex (surfaced as the existing `KB_R0009` for an AFK run or `KB_R0008` for a hook), which is acceptable and operator-actionable — the same stance as a bad Model.

The **level actually used is not reliably observable**, so krutrimbox prints the effort it *passed in* — intent, not confirmation. Claude Code never reports the resolved level (it is absent from the stream-json `init` event, and the invalid-value warning does not name the level it fell back to); Codex prints it only as human text in an `exec` startup banner on stderr, never in its `--json` event stream, and even that banner is version-fragile and subject to a live bug where it can ignore the configured effort. So krutrimbox surfaces the Model and Reasoning Effort it injected in its own run-log lines — the run startup line and each hook agent-action line — including only the knobs actually set.

## Considered Options

- **Validate effort against a per-Agent-Backend allowlist and coerce an invalid value to a default.** Rejected: fragile and redundant. Codex effort validity is per-model and per-CLI-version, not per-backend, so a per-backend list accepts levels a given model cannot run and drifts from the installed build's enum; and Claude already validates-and-falls-back natively. Passthrough is simpler and matches the Model contract.
- **Validate effort against the selected Model.** Rejected for the same reason a Model allowlist was (ADR-0023): per-model effort matrices change with every model and CLI release, so it is unmaintainable.
- **Scrape the actually-used effort from the agent's output to print it.** Rejected: not reliably available. Claude never emits it; Codex emits it only as unstructured, version-fragile stderr banner text. krutrimbox records its own intent instead.
- **Select effort via an environment variable.** Rejected: no uniform env surface — Codex has no reasoning-effort env var (only the `-c` config override) — so the agent argv is again the single seam that covers both backends.

## Consequences

- `buildExecCommand` gains an effort option beside the model; each backend maps it to its own surface (Claude `--effort`, Codex `-c model_reasoning_effort=`). Every other layer stays effort-agnostic.
- The config `agent` Hook Action gains an optional `effort`; `comment` and `command` actions do not.
- krutrimbox's run startup line and each hook agent-action line now name the Model and Reasoning Effort it passed (intent) — the first time either is surfaced from krutrimbox's own knowledge rather than the agent's echo.
- An invalid effort is operator-facing, not a krutrimbox bug: Claude falls back with a warning, Codex coerces or fails the run (`KB_R0009` / `KB_R0008`); krutrimbox never silently substitutes a level of its own.
